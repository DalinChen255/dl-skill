# 小红书私信跟进 Skill

按使用者自己的 CSV 名单，在小红书私信通核查客户、执行已授权的跟进，并保留可恢复的本地记录。

当前版本见 [VERSION](VERSION)，更新内容见 [CHANGELOG](CHANGELOG.md)。

## 能做什么

- 合并多份导出名单、按 UID 去重，保护已留资或明确拒绝联系的客户。
- 核对一个客户在多个账号下的身份、标签及聊天证据；新批次默认每位客户每轮联系一次。
- 使用已批准的原文，执行发送前核对、点击前记录和回执检查；失败或回执不明不会自动重发。
- 保存暂停、待审和异常状态，重启后继续原批次；已结束批次可以只读查看汇总。
- 区分发送消息数、去重客户数和话术观察窗口；复盘时列出账号映射与标签证据的缺口。
- 记录搜索、历史读取、切账号、业务审核和回执核验的耗时与缓存情况，用于实际测量。

## 运行环境

当前实现适配 **Codex Desktop 的 CUA tab API**。它需要已登录小红书私信通的浏览器，以及允许本地模块导入、`node:fs/promises` 文件访问和 `node:child_process` 启动 Python 的执行环境。

建议使用 Python 3.10+ 和 Node.js 24。本轮验证环境为 macOS、Python 3.9.6 / Node.js 24.16.0，其他系统或版本尚未验证；Windows 的目录同步与持久化行为也未验证。Python 使用标准库；浏览器控制能力由宿主提供，不随 Skill 安装。

现有适配器不能直接承诺在 Claude、任意浏览器自动化工具或普通网页 Console 中运行。换宿主需要实现兼容的 tab 接口并重新验收。小红书页面更新也可能需要调整定位器。

## 安装

先在自己选定项目中创建 `.agents/skills/dl-xhs-winback/`。

- 使用单 Skill ZIP 时，ZIP 根目录就是 `SKILL.md`；把 ZIP 的内容解压到刚创建的目录中。
- 使用 Git 仓库源码时，将仓库的 `skills/dl-xhs-winback/` 目录内容复制到刚创建的目录中。

安装后的入口必须是：

```text
你的项目/
  .agents/skills/dl-xhs-winback/
    SKILL.md
    VERSION
    README.md
    agents/
    references/
    scripts/
    examples/
```

不要再套一层同名目录。在 Codex Desktop 打开这个项目，确认能找到 `$dl-xhs-winback`。

从该项目根目录设置路径，并创建该项目独立的数据目录：

```bash
umask 077
SKILL_DIR="$PWD/.agents/skills/dl-xhs-winback"
PRIVATE_DIR="$PWD/.xhs-winback-private"
mkdir -p "$PRIVATE_DIR"
chmod 700 "$PRIVATE_DIR"
python3 "$SKILL_DIR/scripts/self_check.py"
```

`self_check.py` 使用临时数据库和虚构数据，检查本地导入、登记及只读统计能力，不联网、不打开浏览器、不发送消息。通过自检后仍需检查自己的 CUA 环境与页面，不能把本地通过视为现场发送已通过。

把 `/.xhs-winback-private/` 加入项目的 `.gitignore`。每个项目使用自己的 runtime；不要依赖脚本的历史默认路径，不要把全局 Skill 目录旁的 `private/` 用作共享账本。命令行操作数据库时须显式传 `--db`；具体命令见[执行手册](references/execution-runbook.md)。

## 准备自己的名单

需要小红书用户列表的真实导出 CSV，使用 UTF-8 或 UTF-8 BOM 编码。当前导入器要求以下表头全部存在，允许不适用的单元格为空：

```text
用户ID,用户昵称,归属账号,最新进线时间,最近开口时间,最近留资时间,手机号,微信号,留资方式,用户类型
```

`用户ID` 用于匹配真实会话；昵称不能替代 UID。时间字段支持 `YYYY-MM-DD HH:MM:SS`、`YYYY/MM/DD HH:MM:SS` 及对应的纯日期格式，按 `Asia/Shanghai` 解析。保留导出中的留资信息，不要为扩大名单清空这些字段。

把导出文件保存到自己的 runtime。可以合并多个月份；任意已导入表中的明确留资信号都会保护该客户。“全部账号”根据当前页面实际搜索出的会话核查，无需账号配置；指定账号跟进时，需要在自己的 runtime 配置实际账号 ID 和导出名称映射，导入时传 `--config`，登记时设置 `XHS_FOLLOWUP_CONFIG`。话术分析也需要明确账号范围。具体见[执行手册](references/execution-runbook.md)，不能凭名称猜 ID。

[`examples/users.example.csv`](examples/users.example.csv) 和 [`examples/run.example.json`](examples/run.example.json) 只用于展示格式，数据完全虚构。只能用于离线学习或临时自检，**不要导入真实业务账本或拿来执行发送**。

## 用自然语言调用

安装完成后可以这样开始：

> 使用 `$dl-xhs-winback`。先只读检查我提供的 CSV 和当前私信通页面，数据放在这个项目的 `.xhs-winback-private`，显示名单、账号范围和待处理数。

准备发送时，提供实际名单、明确账号范围和完整话术，然后明确要求启动。例如：

> 使用刚核对过的名单和账号范围，按下面这段原文开始本轮跟进，每位客户本轮只联系一次。遇到留资或拒绝联系先停发。话术：……

补标“无意向”涉及页面修改，需另有当前使用者的授权。未授权时会先记录拒绝并停发，报告待补标。作者以前的发送或补标授权不适用于新使用者。

随时说“暂停”，执行器会在当前客户/账号操作边界停下。已经进入当前账号发送段的消息仍可能完成发送和回执记录；以执行器返回的暂停状态为准，不承诺中途撤销这条消息。要继续时明确说“继续原批次”；查看汇总、修改 Skill 或运行测试不会恢复发送。新聊天继续时，告诉它原项目及 runtime，避免另建账本导致丢失发送保护。

也可以要求“查看原批次汇总”或“复盘这次话术”。话术关联只说明观察到的前后关系，不能证明因果；抽样报告不能当作全量留资率。

## 数据和发布边界

公开包只提供代码、说明和虚构示例，不包含作者的客户名单、聊天记录、账号配置、执行日志、数据库、截图或历史业务报告。使用时产生的这些数据只应保存在使用者指定的 runtime，不随 Skill 再发布。

账本、进度文件和对应 `.reviews/` 证据目录需要一起备份。不要删进度、换数据库或清理锁文件来绕过暂停、待核销点击和去重保护。对外分享复盘报告前仍应人工检查脱敏结果，脚本不能保证识别所有隐私内容。

## 已知限制

- 当前适配的是私信通特定页面结构；账号权限、登录状态和平台页面变化会影响运行。
- 自动问询白名单和复盘分类偏咨询、课程等获客场景；其他含义的内容进入审核，其他行业尚未单独验收。
- 默认业务规则不把历史重复话术、普通待回复或固定 24 小时间隔作为单独停发条件。使用前核对自己的业务要求；平台实际拒发仍会记录并跳过，不能绕过限制。
- 身份、标签或历史证据不足时会暂缓；浏览器断连、用户草稿、未核销点击和本地保存失败会停止执行。
- 发送速度受平台响应和会话历史长度影响，以实际批次记录为准。
- 标签修改须在保存后重新读回确认，操作失败会保留为待补标。
