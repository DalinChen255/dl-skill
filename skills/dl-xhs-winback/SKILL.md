# 小红书私信跟进

版本以 [VERSION](VERSION) 为准；日常操作见 [README](README.md)，变更与验收范围见 [CHANGELOG](CHANGELOG.md)。启动或继续前，用 `(await workflow.summary()).startup` 显示版本、名单范围、原话术、触达规则、待处理数、账本状态和当前控制器的暂停/发送开关；查状态本身不恢复发送。

## 运行环境与当前授权

已实现的是 Codex Desktop 的 CUA tab 接口适配。建议 Python 3.10+ 和 Node.js 24；本轮验证环境为 Python 3.9.6 / Node.js 24.16.0，其他版本尚未验证。需要可导入本地模块并访问 `node:fs/promises` 与 `node:child_process` 的执行环境，以及兼容的 CUA tab API；浏览器须由当前使用者登录。这里没有 Claude 或任意浏览器的通用适配器。

默认只读。发送必须由当前使用者给出名单、账号范围、原文话术，并明确启动；暂停后需明确恢复指令。补标“无意向”是独立的页面写入，须有当前使用者授权。没有补标授权时，先持久记录拒绝并停发，报告待补标。安装、检查、修改 Skill 或运行测试不构成发送或补标授权，作者的历史授权不适用于任何新使用者。

本 Skill 的默认业务规则会继续跟进未触发留资、无意向或拒绝联系保护的候选，使用前应向当前使用者说明。用户提出更窄范围时遵从其范围；若要求放开保护或改变脚本未支持的资格规则，先停止相关执行并说明。

## 输入和范围

- 用户提供一个或多个 CSV、发送范围、原文并启动发送。接受用户指定的历史月份，不要求重新导出当天 CSV。
- **全部账号**：合并 CSV、按 UID 去重；任意表内已留资的 UID 直接排除。直接在当前已登录的私信通搜 UID，以实际搜索出的会话为范围；不预先枚举账号，不筛选账号，不因 CSV 旧账号名称无法映射而漏掉 UID。
- 指定账号时才解析该次指定范围；实际 UID 和会话身份始终核对，防止发错人。
- 广告和自然流可用同一原文：相同时来源未知不阻塞发送，统计记 unknown；不同文案时才需要来源明确。原文不自动改写。

## 一位客户的最短流程

1. 搜 UID：先让旧搜索失焦，整串填入；等真实浮层结果，必要时才补回车。短暂的“暂无匹配的用户”不能当作最终无结果；点击后等目标 UID 和会话身份加载完成。
2. 逐个打开该 UID 的会话，核对身份、标签和聊天中的留资/停止联系证据。任意一个会话出现停止条件，整个 UID 停发；已经确认停止即可结束其余发送检查。
3. 排除条件只有：标签“留客资”；标签“无意向”；已留下手机号/微信、明确表示已添加；明确要求不再联系。仅点击企微卡不等于已添加。
4. 客户明确说“别再联系”“不要再发”等时，先记录整个 UID 停发，有当前使用者的补标授权时，再在出现该请求的会话补标“无意向”并读回验证；否则报告待补标。保留原有留资证据。标注失败单独报告，仍然停发；不要因为普通的“不需要某份资料”或引用他人话语自动打标签。
5. 全部相关会话检查通过后，按已登记的触达规则发送用户原文并核验送达。新批次默认 `uid_once`：每位客户每轮只联系一次，选择最近有真实互动的合适账号；旧批次保留已登记规则，若为 `account_once`，只继续尚未成功的会话。任一失败或待核实不能靠换账号重试。读取后尽量停在拟发送会话，其他已检查会话复用本次证据和历史边界。

**默认未设置的业务门槛：**客户必须主动打过字、不是同行、没有待回复、最近我方消息满 24 小时、以前从未收过相同话术。平台实际拒发时保存原提示，按下方范围处理，不绕过限制、不重复点击。

聊天意义由执行代理结合真实上下文确认；脚本的关键词只提示候选证据，不直接决定无意向标签。需要看历史时用“加载更多”；首次看完，后续只增量核对。`history_complete=true` 可以来自已核实的缓存边界，不能因为 `history_from_start_complete=false` 再次暂缓。图片等内容需要视觉阅读，不用“未知类型”一律排除。我方微信号、客户说“我加你/准备加”不是客户已经留资。

## 连续批次执行（默认）

使用 `batchMode:true` 的 `runSlice`，默认每段约 20 秒。简单、完整且无歧义的问询由有限白名单处理；其余进入持久待审队列，代理一次阅读多位的完整上下文，再提交逐账号结论。不能批量无依据填 false，也不再每遇到一个需要阅读的客户就结束整批。

已通过审核的客户优先执行；`maxReviews` 限制新客户进入普通待审队列。已通过客户复核时出现新风险，必须重新入审，即使暂时超过该上限。读完仍无法确认的客户，用 `holdReviews([{uid,evidence_id,reason}])` 保留证据和具体原因，移入独立暂挂队列；其余客户继续。暂挂客户仍然停发，结束时单列，后续只能依据真实审核结论解除。

每段之后取 `reviewPackets({queue:'pending',limit:12})`，完整阅读本批、提交已明确的结论、暂挂未明确的客户。发送授权有效且未暂停时，用 `submitReviewsAndRunSlice(approvals,{limit:50,maxDurationMs:20000,maxReviews:12})` 在一次调用中保存审核并接着执行有界批次。该接口仍先重新核对页面，不并发控制浏览器。暂停期间仅保存审核，使用 `submitReviews`，详细只读配置见执行手册。

已审核历史长期保存原文和边界。模型阅读花了几分钟，不等于页面故障；执行前重新核对当前范围、身份、标签、草稿和新增消息即可。原账号历史的消息 ID、内容、类型等未变，且新增内容只有可提取的我方文字、平台文字提示或白名单客户问询时，复用旧历史和图片审核。新增客户歧义文字、新媒体、新账号或历史变化必须重新判定。完整历史缺少旧消息时以当前快照为准，不从缓存补回。历史证据和短期页面状态分开保存，待审不占发送名额。

进度只保存证据引用，完整聊天单独私密存储，避免名单越大写入越慢。同一 private 目录只允许一个执行器操作；暂停状态和待审材料跨重启保留。详细接口、互斥锁恢复和验收口径见执行手册及 [批次设计](references/batch-design.md)。

## 稳定性和停止条件

身份核验、用户草稿保护、发送前原文读回、点击前落账、成功回执核验必须保留。点击后先读页面顶部弹窗；平台明确拒发时记录原提示和失败原因。只有稳定新消息和原文匹配才计发送成功，临时气泡、“重新发送”不计成功。

发送异常统一跳过，不要求先查明原因才能继续：

- 隐私设置、24 小时/条数限制、其他明确拒发，或本次消息显示“重新发送”：记 `failed` 和实际提示，跳过该 UID 本轮剩余发送，继续下一位。没捕获原因就记未知，不为追原因反复点击或停整批。
- 点击后没有明确成功或失败回执：保留 `uncertain`，跳过并隔离该 UID，其他客户继续。后续运行也不自动重发这个 UID；结束时单列待核实名单，不能伪装成失败或成功。
- 发送异常不计入“连续 3 个读页异常”。本轮失败、待核实都不重试，不点击“重新发送”，不绕过平台限制，也不因此给客户补标“无意向”。
- 单个 UID 搜索/历史未读全，记录暂缓并继续主队列，末尾最多慢速核查一次。同一 UID 内部重读只计一次故障，完整核查成功后清零连续故障计数。
- 连续 3 个不同 UID 核查失败，先用本轮已核验的正常客户做有上限的只读健康核查。对照仍正常则隔离异常客户并继续；整体无法核查才恢复页面或报告阻塞。累计无进展也有上限，不反复重置计数。具体步骤见执行手册第 5 节。
- 整体页面无法操作、浏览器断连、登录失效、无法保证目标身份、用户草稿需要保护、reserved/clicked 尚未落账或本地保存失败时，暂停处理并保存可保留的现场；分别报告具体原因。

5 分钟未完成首个有效会话核查就说明阻塞。修工具时暂停业务执行；修复必须在原故障页面只读复验，本地测试通过不等于批量发送已稳定。进度报告包含实际成功数。

## 工具入口

安装目录保存公开代码。每个项目必须显式指定独立 runtime，例如项目根目录的 `$PWD/.xhs-winback-private`；CSV、SQLite 账本、进度、聊天证据、截图和报告均存入该目录，权限设为 0700，不提交 Git。所有 Python 账本命令显式传 `--db`，JavaScript 桥接显式传 `dbPath`；不要依赖脚本的历史默认路径，也不要把全局 Skill 安装目录旁的 `private/` 当成所有项目共享的数据目录。初始化步骤见执行手册。

- 发送或恢复：读 [执行手册](references/execution-runbook.md) 的发送部分；操作页面时读 [页面约定](references/browser-contract.md)。
- 业务判定：读 [资格规则](references/eligibility-rules.md)。
- 话术复盘：仅在请求分析时读执行手册的分析部分。抽样不冒充全量留资率。
- `daily_import.py` 导入 CSV；`daily_followup_state.py` 管理发送账本及无意向补标；`xhs_followup_cua_adapter.mjs` 通过当前 CUA tab 操作页面。
- 正常执行使用 `xhs_followup_workflow.mjs` 串起观察、业务阅读、准备、点击和落账；`xhs_followup_local_bridge.mjs` 只负责本地账本和进度文件。默认只读；不要每次在 REPL 重写临时循环，不混用新旧适配器实例。
- 正常使用 `runSlice({limit:50,maxDurationMs:20000,maxReviews:12})` 取有界队列，不逐人导出/打印全队列。每个用户请求保存稳定的 session 基线；恢复或上下文压缩沿用原 session，报告区分“本次继续新增”与“当天累计”。

不自动创建定时任务。用户说继续时先核销未落账的 reserved/clicked；已登记 uncertain 的 UID 保持隔离，其他客户恢复同一轮。跨日默认重新登记；用户明确要求发完原名单时，按执行手册调用带明确数据库路径的 `authorize-remaining` 记录同批次续接授权，继续原名单并保留真实时间、原话术及全部去重和停发保护。结束时统一报告成功送达、发送失败、回执待核实、留资/无意向跳过及补标结果；发送问题附 UID、账号和原因名单，未知原因如实写未知。效果只能表述为观察关联。
