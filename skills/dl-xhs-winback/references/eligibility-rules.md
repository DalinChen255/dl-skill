# 发送资格与保护规则

## 按 UID 排除

- 任意导入表出现明确留资字段，排除该 UID；旧表无账号映射也有效。
- 搜索出的任意会话有“留客资”或“无意向”，整个 UID 停发。
- 聊天中客户已经提供手机号/微信，或明确说已经添加，整个 UID 停发。结合语境辨认客户联系方式，不把我方发出的号码、产品编号、问题或假设当作已留资。
- 客户明确要求不再联系，整个 UID 停发，补标须有当前使用者授权；有授权时给提出拒绝的会话补标“无意向”，没有授权时报告待补标。引用、否定句和仅不需要某项资料不等于退订。
- 点击企微卡、同行身份、没有主动打字、客户有新回复、最近发过文字、历史上收过相同话术，不是排除理由。
- 客户说“我加你”“打算加”只表示意向，不是“已经添加”；我方发出的微信号也不能算客户已留联系方式。

已留资保护与效果统计分开：只有已核实 UID 的平台“留客资”标签计标签成果；手机号、微信和“已加”是停止发送证据，不自动冒充新增标签。

## 必要的执行检查

- 搜索结果实际完成，所有结果都已打开核实；身份必须是目标 UID。`all` 的会话范围来自本次 UI，不来自旧账号名单。
- 浏览器脚本读到聊天起点或已经完成业务阅读的旧边界；执行代理只需判断“是否已留资、是否明确停止联系”。批次可以复用已审核的完整历史，有限无歧义完整问询由经过测试的白名单判断；其他客户全文集中提交审核。`confirmBusinessReview` 是对已读证据的确认，不是再向用户申请许可。未显示的聊天不能猜。
- 图片/无法提取的内容从页面视觉阅读。来源信息与标签分别处理：标签未加载不能发送；同原文时来源未知可以发送。
- 用户草稿不覆盖。页面发生新消息或身份变化时重读变化部分，不自动把“客户回复了”当作排除。
- 新批次每轮同一 UID 只触达一次，优先最近真实互动的合适账号；旧批次保留已登记的逐会话规则。所有相关账号的保护证据仍须核查。中断后先核销已点击的发送，不自动再次点击；失败/待核实不换账号重试。前一轮用过同话术不再阻挡新一轮授权发送。
- 不自行设 24 小时业务间隔。遇平台实际限制、失败或不明回执，按失败流程处理，不绕过限制。

## 无意向补标

先让 `record-reviewed-history`（批次审核）或 `prepare-touch`（单步诊断）保存明确的客户拒绝原文，得到 `label_updates`；这是耐久的停发记录。当前使用者已授权补标时，再通过当前 UI 的客资标签控件选择“无意向”，按页面需要保存并重新读取。未获补标授权时保持停发并报告 pending，不改页面标签。保留已有标签和联系信息；已有“留客资”时不抹去留资事实。

调用 `record-no-intent` 保存读回结果；只有核实 UID、会话、标签、时间才记 verified。失败记 failed，报告待补标；failed/pending 同样阻止该 UID 后续发送。重启后根据报告及当前有效的补标授权处理标签，不重发私信。

## 效果口径

累计留资按去重 UID 计一次。原有标签不算本次新增；没有平台发生时间时只说首次发现时间。话术观察窗口最长 7 天，不限制跟进次数；关联到首次标签发现前最后一次有效发送，不声称因果。员工干预与未知来源单列。均衡抽样只用于话术诊断，不能计算总体留资率。
