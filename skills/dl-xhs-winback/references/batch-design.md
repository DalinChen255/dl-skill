# 连续批次执行设计

批次流程在保留身份、客户保护和回执检查的前提下，减少重复读取。性能记录包含搜索、读历史、切账号、业务审核、回执核验的耗时，以及缓存命中和重新读取原因。发送吞吐量必须用包含审核、失败和恢复的真实墙钟时间测量，不能用只读页面速度推算。

## 执行方式

一个 CUA 执行器控制一个页面。每个时间片默认最多 20 秒，操作使用当前受支持的 UI 方法；到边界返回统计和待审包。一次工具调用内串行处理多个 UID，不并发切换同一页面。用户暂停后不开始下一位；已进入当前账号发送段的消息可能仍完成发送及回执落账，暂停在该段结束的边界生效。

普通路径只接受完整身份、范围、历史证据。全文没有客户内容，或每条客户内容均为有限的、无联系方式与确认歧义的完整问询模板时，可自动判断。数字、泛化的“好/是/已加”、未知内容、图片和引用卡片不通过宽松关键词推断。

其余客户入持久待审队列，一次返回多位的完整聊天上下文。代理按 UID 和账号逐一给出决定，附证据指纹；审批记录只授权这些证据，不是可直接重放的浏览器令牌。已审核历史保存边界与原文；随后重新搜索真实会话范围、确认身份/标签/新增消息。原历史未变且新增仅为可提取我方文字、平台文字提示或白名单客户问询时，复用历史视觉审批。新账号、新媒体、客户其他新表述或旧历史变化需重新判定。

普通待审与暂挂分开持久保存。只有实际阅读后仍未明确的客户才按证据指纹和原因暂挂，不占普通入审上限，仍然停发。已审批待执行项优先于新客户入审；新风险必须重新入审。读完本批后，一次 `submitReviewsAndRunSlice` 保存结论并重新核查、执行下一有界片段。未解决材料保留，结束统一报告。

首次完整阅读后增量检查；长久可复用的是历史判断。发送所需的当前页面身份、草稿、标签、范围和最新消息，始终现场确认。不能用过期令牌直接点击，也不能因审核等待超时就把客户计为浏览器读取故障。

## 状态与异常

待审核、已审核待执行、已跳过、失败、回执不明和完成分别持久化。待审材料不占用 reserved/clicked；批次重启后先核对真实未核销发送，再恢复待办。失败/回执不明隔离整个 UID；单客户读取失败走末尾的一次慢查。真实页面整体故障按既有恢复上限处理。

进度记录从上次返回到下次调用的等待时间、页面时间、语义审核时间、落账时间，以及处理 UID、实际发送、失败、普通待审和暂挂数。不能只统计浏览器耗时。各审核任务的等待时间有重叠，不能把其累计当作墙钟时间。选下一批时，先排除本地等待项再截取数量，避免等待队列占满取数窗口。

## 验证

1. 临时账本验证：跨账号留资、拆分号码、普通问询、客户确认已添加、拒绝联系、未知媒体、账号范围变化、待审重启、过期后重查、暂停、失败继续、重复发送防护。
2. 在当前使用者授权范围内只读核查真实队列：验证搜索/历史/批次提交，保存各阶段耗时，明确新增发送为零。首次读取与已审核增量读取分别测量。
3. 当前使用者明确授权正式发送后，才在实际业务批次测量真实回执与吞吐量。安装或修改 Skill 不自动授权发送。
4. 对照目标审计：未测项保留未完成，不以少数样本或本地测试代替整批验收。


离线性能、只读页面性能和实际发送性能分开报告。同一组样本分别测首次读取与增量读取，并记录样本规模；缓存复用不等于已证明长期提速，不因性能目标减少保护检查或并发操作同一页面。
