# 私信通页面约定

当前适配的路由是 `/im/multiCustomerService`，左侧私信通，右侧客资标注。使用 Codex Desktop 当前受支持的 CUA tab API；evaluate 只读 DOM，点击/输入/滚动使用受支持的 UI 方法。发送暂停期间不发消息、不改标签；修复可对原故障会话做只读复验，不把修 Skill 当作恢复发送。

## 搜索和会话

- 主路径是“输入用户ID/小红书ID”。不筛选账号、不切换回复模式。先点消息顶部安全区域让旧搜索失焦，清空后一次填入完整 UID，等待 `.search-contact-item` 浮层结果。整串填入可触发搜索，已有结果不按回车；首段等待无结果时才补一次回车。下一个 UID、同 UID 的下一条会话都重置焦点。
- 普通搜索先等待最多 1.6 秒，必要时延长，总搜索窗口最多 6.5 秒且不超 UID 剩余预算。临时“暂无匹配的用户”不能证明没有客户；记录实际输入值、可见/总结果数、加载提示、等待错误和耗时。不能仅用两秒内没取到节点宣告平台搜索异常。
- 左侧原会话列表可以和搜索浮层并存，原列表不更新不是平台故障的证据。没有读到浮层不能宣布“没有客户”；记 `search_result_not_confirmed`，核查输入触发/等待，最多恢复一次。
- 浮层结果用当前可见 `.search-contact-item` 的索引定位并点击；点击前重读条目，防止浮层变化后误点。搜索结果中的昵称不能单独证明身份。核对右侧 UID 与当前聊天区可见 `jarvis-msg-` 的 UID/账号；若左侧有 `.sx-contact-item.active[data-key]`，也要与它一致。搜索打开的会话可能没有左侧 active 行，不能因此否定已核实的会话。消息 ID 支持用户与账号两种前后顺序，不使用残留的上一位消息。
- 点击后右侧 UID 可能短暂为空；等待目标身份和标签加载，最多 3 秒且不超 UID 预算。隐藏节点和仍显示加载中的旧结果不算本次可用结果。已核实的账号可优先定位对应浮层条目，仍须重新验证真实 UID/账号。
- 浏览器定位器返回 0 或点击超时，但只读 DOM 仍显示浮层时，重新读取搜索值和同一条目的内容、索引及可见位置；全部未变才用当前坐标点击一次。打开后仍核对 UID、账号和标签。结果变化则暂缓，不猜坐标。
- `scopeMode:all` 根据实际搜出的会话动态形成范围，不把旧 CSV 账号当作必须逐一寻找的名单。多个结果必须全部检查后才发送；发现全 UID 停止条件可提前结束发送检查。
- 搜索滚动容器只在 `.search-user` 内寻找；外层页面的小幅滚动不能当作搜索结果还有下一页。某个结果必须打开并确认身份后才记为已检查，身份暂未加载可重新定位一次；成功恢复后不保留虚假的未解决计数。

## 标签和消息

`#rightPanel` 的“客资标签”精确读取“留客资”“无意向”；两个状态可以并存，保留留资事实。标签已加载和归因已加载分别判断。相同原文下归因缺失不影响发送。

消息 left 为客户、right 为我方、center 为系统。普通文字可能使用 `.text-message[msgcontainertype=""]`，也可能用旧 `.msg-container/.msg-wrap`。GENERAL 不必然是卡片。无法识别类型时呈现原文/视觉证据，由代理判断，不能据此断言不符合发送条件。

首次需要查看保护性证据的全部历史，后续可读到已完成业务阅读的旧边界。`history_complete=true` 且 `history_reached_prior_boundary=true` 是完整增量核查，`history_from_start_complete=false` 不否定它。加载控件消失或点击后消息尚未更新时，在 UID 预算内等待状态稳定；不能沿用旧“还有更多”的判断，也不能一次快照不变就立即判失败。长记录允许暂缓，但要报告具体读取障碍。

聊天是虚拟列表：只取 `#pro-msg-box` 内本 UID 的活跃节点，排除 `data-active=false` 缓存；保留当前账号已读取的消息并按消息 ID 合并。节点数量不变仍可能出现更早消息。未挂载“加载更多”时先核对滚动边界，必要时向上滚动，不能直接宣布历史完整；读取后回到最新消息处核验边界。当前 `recyScroll1` 从最新向最早排列，向上滚动时 scrollTop 增大。

历史加载定位器返回 0 时，仅在当前身份仍匹配、唯一活跃“加载更多”控件未被遮挡且位置经过重新读取时，允许通过当前坐标点击。随后仍验证更早消息和完整边界；无法证明完整就暂缓。

`observeUid` 返回完整已加载文字（分析模式仍按采样上限），不得只读末尾几条就声称看过全部。关键词是提示；默认批次路径由 `xhs_business_review.mjs` 的有限完整问询白名单或代理全文阅读给出判断，再由工作流使用 `confirmBusinessReview` 明确填入 contact_shared、stop_contact；明确拒绝必须带客户原话。不要用正则独自决定标签，也不要把业务阅读转成再次询问用户。

## 补标无意向

只有当前使用者明确授权补标时才执行此动作；作者的历史授权不适用。未授权时先记录停发并报告待补标。先有账本停发记录，再重新核对出现拒绝的目标 UID/会话。读取当前“客资标签”控件和打开后的选项，用当前可见 locator 点击“无意向”；有保存按钮则保存。重新读回标签才记成功。控件结构参考：`#rightPanel .info-item-select` 标签选择器及“跟进中、留客资、高潜成交、成单、无意向”选项。运行时须重新读取当前控件，不能把已观察结构当作平台永久契约；失败记录待补标，UID 仍停发。

## 发送和回执

当前适配的输入框为 `textarea.reply-textarea`，上限 500 字；已有用户草稿保留。填入后读回原文，点击前写账本，点击一次。点击前后比较页面提示，避免把旧提示归给本次点击。点击后立即读页面顶部弹窗和当前会话：

- “由于对方隐私设置，你无法发送消息”记 `failed/platform_privacy_restriction`。
- “你今天已经发送1条文字消息，请耐心等待回复”记 `failed/platform_daily_text_limit`。
- 本次新气泡正文匹配、时间不早于本次点击且明确显示“重新发送”，记 `failed/platform_send_failed`，原因未捕获就说明未知；旧气泡重新挂载和其他正文的失败标记不能用于判断本次发送。
- 新右侧稳定 ID、账号、时间和正文均匹配且无失败标记才成功；只有临时气泡、没有明确回执或点击后读回出错时记 `uncertain`。

回执使用实际时间窗口：默认最多 8 秒，未出结果时约每 250 毫秒读一次；明确成功/拒发立即结束等待。不能以“读了 24 次”等同已经等待足够时间。现场以真实回执为准，回执不明不得自动重发。

失败和待核实都跳过该 UID，落账后继续其他客户，结束统一汇报，不自动补发、不点击“重新发送”。旧聊天里的 24 小时提示只作背景，不自行设发送间隔门槛。

不能把主账号名称出现在授权会话中直接当作失败原因；当前单账号模式无需手动切换发送账号。发送失败直接记录跳过，不为追原因停批量，也不擅自改回复模式。

其他会话已经检查且仍在 120 秒证据有效期内，可用 `selectReviewedAccount` 只定位并轻量核验，无需整 UID 重读。身份、标签或最新消息边界变化则重读变化部分。连续故障按不同 UID 计数，恢复步骤见执行手册第 5 节；不边发送边改代码。

历史语义批准持久保存；120 秒时限仅约束当前发送所需的页面观察。批次待审回来后重新 observe，并结合已审批边界增量阅读，不能将模型等待时间算作搜索故障。连接中断、本地证据丢失和真实搜索浮层未确认分别报告。
